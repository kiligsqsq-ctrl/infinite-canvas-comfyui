# Pending Tests

The current release needs manual verification in these areas:

- Core-only navigation: the header should retain Canvases, Assets, Settings, and the temporarily retained Agent only; the homepage should contain no showcase; image workbench, video workbench, prompt library, documentation, GitHub, and version entries and routes should be unavailable; prompt-source syncing and prompt pickers should be absent; WebDAV should sync only canvases and assets.
- Homepage branding: the original dark artwork should remain legible behind the centered heading and call to action, while the new infinite-connection canvas mark should render clearly in both the top navigation and browser favicon.
- Separate media upload: the node picker should offer independent image, video, and audio upload actions; each picker should accept only its media type and allow multiple files, create populated media nodes near the menu position, and never open or trigger generation. Media and generation-node toolbars should no longer expose upload or replace actions, while the separate bottom-toolbar upload remains available.
- Canvas navigation: the bottom toolbar should switch between Select and Move modes and reflect the active mode with its icon; Select should draw a clearly spaced dashed range whose dash length, gap, and stroke width remain visually constant at every zoom level, while Move should pan from either the background or a node. Clicking blank canvas space in either mode should deselect the current node and close its top toolbar and lower prompt panel. Holding Control or Space should temporarily invert the active tool without changing the toolbar mode: Select becomes Move, and Move becomes range selection. After clicking any canvas-page button, pressing Space should only invert the tool and must not trigger that button again. Middle-button panning and additive node selection with Shift/Cmd should continue to work, while Space remains available inside text inputs and editable content.
- English and Simplified Chinese switching across navigation, settings, titles, descriptions, Ant Design components, and persisted preferences.
- Global Dropdown, Menu, Select, Cascader, and TreeSelect popup backgrounds, hover states, and selected states in both light and dark themes.
- Canvas node resize stability, prompt scrolling, generated-prompt restoration, edit-prompt persistence after closing an existing image or text node panel, expanded prompt editing with live synchronization and `@` references, image editing, drag-and-drop references, and generation configuration.
- Canvas side panel: clicking an element row should smoothly center and select its node without zooming above 100%; image elements with content should still open the large preview without triggering canvas focus.
- Multi-image canvas generation: starting N images should immediately create one image node with N expandable slots and one incoming connection; each empty slot should independently show generating or failure while requests are running, every slot with image content should always display that image, and the first successful image should appear as the primary image immediately. The collapsed state should use a compact stack with at most three closely spaced backplates and a clearly legible count control; clicking the control should hide the floating toolbar and expand the slots upward and to the right. Every completed secondary image should keep a clearly legible primary-image action visible in both themes, and clicking the empty canvas should collapse the group.
- Multi-image primary selection: choosing another primary image should preserve the node center and current maximum edge while adapting to the new image ratio; free-resize nodes should keep their exact dimensions, and the viewport zoom indicator must not change.
- Failed multi-image slots: every failed slot, including the current primary slot, should expose retry and delete actions. Retry should update only that slot without replacing an existing successful primary image; delete should remove only that failed slot and update the displayed count.
- Multi-image resize: starting a resize while child images are expanded should collapse the group once, then resize the root node normally without triggering nested React updates or an application error.
- Multi-image alternatives: expanded images should use up to four columns so larger batches stay compact; every completed image, including the primary image, should provide an independent download action, while alternatives should also keep clearly legible create-copy and set-primary actions in both themes. Create-copy should add an independent image node to the right of the group, select it, and leave the original image group unchanged.
- Canvas Agent startup, MCP status, model and permission controls, approvals, version reporting, diagnostics, streaming responses, history consistency, multi-tab isolation, and local Skill management.
- Agent header tabs in English and Chinese at different panel widths; labels should collapse to icons and counts before either edge is clipped.
- Agent message layout, Markdown, code blocks, attachments, token statistics, progress timelines, command groups, and scroll-follow behavior.
- Agent inline references: type `/` to select an enabled Skill or `@` to select a canvas asset at the caret; tokens should remain aligned with text, support keyboard navigation and hover previews, and preserve their positions after sending or refreshing.
- Agent message metadata: image attachments, Skills, canvas references, and local previews should survive page refreshes and Agent restarts through exact `clientMessageId`, `threadId`, and `turnId` ownership; protocol upgrades must not reset the independent storage format, unknown or damaged storage must refuse writes without overwriting files, no records may be silently pruned by count or size, and deleting a thread should remove its metadata and preview assets without relying on browser IndexedDB or text matching.
- ComfyUI workflow references: a mapped video workflow should upload connected images, videos, and audio files in canvas order, fill only the participating slots, and remove unused media-loader nodes.
- Quick local connections: Settings should add ComfyUI, Ollama, LM Studio, and a generic OpenAI-compatible local endpoint in one click; the ComfyUI preset should include the MiniMax-H3 video model, while the other presets can fetch `/models` or accept manual names. Test connection should call `/system_stats` for ComfyUI and `/models` for compatible APIs. Loopback and private-network endpoints must save and run with an empty API key and must not send an empty Bearer header. Remote cloud providers must still require an API key. Local provider editing should explain service startup and CORS requirements.
- Self-service ComfyUI workflow import: image, video, and audio model rows in a ComfyUI provider should expose Upload API workflow. Import should detect and allow editing prompt, duration, ratio, megapixels, seed, ordered media slots, and the output node; show mapped fields, slot counts, and missing required fields; reject broken node references; and recognize MiniMax-H3 primitive prompt/duration inputs through their graph links. Check this ComfyUI should use the standard `/object_info` endpoint to list missing node types across official, source, desktop, and third-party builds, while explaining that model/VAE/CLIP/LoRA files are not checked. The mapping should persist across reloads, fill references in canvas order, remove unused loaders, delete local workflow data when cleared, and require a workflow before a ComfyUI model can generate.
- Canvas keyboard deletion: Backspace/Delete should remove selected nodes after a non-editable node control receives focus and prevent browser navigation, while inputs, editable text, modals, and popup controls retain their normal keyboard behavior without deleting canvas nodes.
- ComfyUI backend cancellation: stopping a generation that uses an imported ComfyUI workflow should stop frontend polling and cancel the matching queued or running prompt by ID, falling back safely for older ComfyUI versions without interrupting an unrelated job.
- Pre-generation check: the check action on regular generation panels and configuration nodes should show the final prompt, provider, model, parameters, output location, and references in actual send order. A mapped ComfyUI workflow should show slot usage and output node, block confirmation for reference overflow or a missing local mapping, and continue through the existing generation path after confirmation.
- Local repository update: when the canvas is started with `bun run dev`, the cloud-download action in the top-right should fast-forward a clean local `main` branch specifically from `kiligsqsq-ctrl/infinite-canvas-comfyui/main` and reload the page, report when already current, and safely stop for local changes, another local branch, divergent history, a non-Git installation, or an unavailable local update service.
- Video ratio and duration settings: every video model should use ratio-only presets (`1:1`, `2:3`, `3:2`, `3:4`, `4:3`, `9:16`, `16:9`, `21:9`), editable W/H fields, 5s/10s/15s duration presets, and a custom duration input. MiniMax-H3 alone should show 0.4 MP and 0.9 MP presets plus 32-aligned dimensions on ratio cards; switching models should hide those MP presets. Imported H3 workflows should receive megapixels, ratio, custom dimensions, and custom duration values.
- Settings import/export, Volcengine Ark protocol handling, and WebDAV-related configuration.
- Local storage settings: the Settings page should provide a Local storage tab that reads only the `infinite-canvas` database and shows IndexedDB usage, total site usage, browser quota, quota percentage, and per-object-store record counts and content size; refreshing after local data changes should update the figures without blocking the rest of the page.

- Local service status center: the Providers tab should list configured ComfyUI, Ollama, LM Studio, and generic local endpoints, automatically show checking/online/offline states, and report latency plus the ComfyUI version or model count. Unreachable checks should finish after roughly eight seconds, and cloud providers must stay out of this list.
- Generation task center: the canvas top-right action should show the active count and list this canvas's queued, running, completed, failed, and canceled tasks. Active tasks should support cancellation, every task should support node focus, finished records should be removable, restored active records should become canceled after a refresh, and tasks from other canvases must remain separate.
- Automatic reference ordering: connected image, video, audio, and text nodes should be numbered top-to-bottom and then left-to-right within each media kind, with complete labels shown near the source side of each reference connection. Moving nodes should update numbering, while explicit `@` token order in the configuration composer must remain authoritative for the actual request.
- Missing local media and relinking: reopening a canvas whose IndexedDB media is unavailable should show a top-right missing count and list exact image, video, audio, or multi-image slots. Relinking a same-kind original file should restore content without changing node layout, other batch images, or connections; mismatched file types should be rejected and the warning should disappear after all items are restored.

The Chinese version contains the complete item-by-item acceptance checklist.
